# Task.md

## Контекст выполнения
Проект представляет собой веб-приложение на микрофреймворке Flask (игра «Крестики-Нолики»), спроектированное по принципам многослойной архитектуры (Clean Architecture / Layered Architecture) с внедрением зависимостей и реализацией алгоритма «Минимакс» для ИИ.

---

## Task 1. Создание структуры проекта
Организовать модульную структуру веб-приложения по слоям:
- **`web`**: взаимодействие с клиентом (`model`, `module`, `route`, `mapper`).
- **`domain`**: бизнес-логика приложения (`model`, `service`).
- **`datasource`**: слой работы с данными (`model`, `repository`, `mapper`).
- **`di`**: контейнер внедрения зависимостей.

---

## Task 2. Реализация Domain-слоя
Реализовать бизнес-логику игры:
- Модель игрового поля (матрица) и модель игры (с UUID и полем).
- Интерфейс сервиса, включающий:
  - Метод расчета следующего хода ИИ с помощью алгоритма **Минимакс**.
  - Метод валидации поля (проверка неизменности предыдущих ходов).
  - Метод проверки окончания игры.

---

## Task 3. Реализация Datasource-слоя
Реализовать хранение данных:
- Потокобезопасное хранилище текущих игровых сессий.
- Мапперы между `domain` и `datasource` моделями.
- Репозиторий для сохранения и получения игровых сессий.

---

## Task 4. Реализация Web-слоя
Реализовать HTTP-интерфейс на Flask:
- REST API эндпоинт `POST /game/<uuid>`: принимает обновленное пользователем состояние игрового поля, рассчитывает ответный ход компьютера через сервис и возвращает актуальное состояние игры.
- Валидация входных данных, обработка ошибок и поддержка одновременной игры нескольких пользователей.

---

## Task 5. Реализация DI-слоя
- Реализовать класс `Container` для описания графа зависимостей (включая потокобезопасное хранилище в качестве Singleton, репозиторий и сервисы).
